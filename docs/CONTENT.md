# Доставка и автоматическое обновление тестов

## Компоненты

1. НЦТ публикует PDF заданий и ключей. Для таджикской версии используется страница https://www.ntc.tj/tj/ba-dovtalab/testho.html.
2. GitHub Actions запускает tools/sync_ntc.py. Импорт выполняется на runner, телефон PDF не обрабатывает.
3. tools/content.py создаёт текстовые банки, необходимые WebP и полные ZIP-пакеты предметов.
4. tools/publish_content.py публикует их в ветку content. Телефон читает HTTPS-файлы с raw.githubusercontent.com.
5. ContentRepository объединяет сетевой каталог и установленные локальные версии. Интерфейс получает готовые вопросы через PrepViewModel.

Платный сервер, API-ключи в APK и учётные записи пользователей для этой схемы не нужны. GitHub используется как первоначальное хранилище статических файлов; при росте трафика базовый URL можно перенести в объектное хранилище/CDN.

## Два режима приложения

- **Онлайн:** загружается JSON выбранного предмета с текстом и ключами, случайно выбираются 25 вопросов, затем скачиваются только их визуальные фрагменты. В постоянный каталог офлайн-предметов этот банк не устанавливается. После подготовки все 25 вопросов доступны при кратком обрыве связи.
- **Офлайн:** пользователь скачивает ZIP предмета или все недостающие предметы кластера. Пакет проверяется и устанавливается целиком. Общие предметы разных кластеров занимают место один раз.

Это не обработка PDF в реальном времени при каждом открытии вопроса: опубликованная база уже подготовлена из материалов НЦТ.

Загрузки выполняются, пока приложение открыто. ViewModel сохраняет операцию при повороте экрана. После завершения процесса незаконченный пакет не считается установленным; его можно скачать заново. Возобновления с произвольного байта и фонового WorkManager в этой версии нет.

## Формат

Корень ветки content:

    catalog.json
    banks/<subject>/<version>/bank.json
    banks/<subject>/<version>/pack.zip
    banks/<subject>/<version>/questions/<subject>/*.webp

catalog.json содержит schema=1, год и список предметов. Для каждого предмета указаны id, version, year, count, path, bankSha256, packSha256, packBytes, unpackedBytes и происхождение исходных PDF.

Версия — SHA-256 от года и нормализованного JSON. Для каждого визуального фрагмента JSON также содержит SHA-256 изображения; изменение картинки меняет версию банка. Обычные текстовые фрагменты доставляются без растровых копий.

pack.zip содержит bank.json и только используемые визуальные фрагменты. Фиксированные timestamps, атрибуты ZIP и несжатые записи обеспечивают одинаковые байты на Windows/Linux; сами WebP уже сжаты.

catalog.json можно заменить. Существующие файлы версий неизменяемы: публикация отклоняется при попытке изменить их содержимое. Старые версии сохраняются, чтобы начатая загрузка оставалась доступной после обновления каталога.

В APK включён только app/src/main/bootstrap/catalog.json. Банки из app/src/main/assets остаются исходным материалом для первоначальной публикации, но исключены из Android sourceSet assets.

## Целостность и установка

- Сетевые пути должны соответствовать banks/<известный предмет>/<64-символьная версия>/.
- Разрешены HTTPS, ограниченные размеры файлов и тайм-ауты запросов.
- Проверяются SHA-256 банка, архива и изображений, количество вопросов, уникальность ID и индексы ответов.
- ZIP распаковывается во временный каталог с защитой от выхода за его пределы, повторных имён и превышения заявленного размера.
- Указатель установленной версии меняется атомарно после завершения всех проверок. Отмена или ошибка загрузки сохраняет предыдущую установленную версию.
- Каждая попытка получает отдельную локальную копию своих 25 вопросов и картинок. Обновление/удаление офлайн-пакета не меняет её ответы.
- При восстановлении процесса проверяются сохранённый JSON и изображения попытки. SavedStateHandle хранит позицию и выбранные ответы; постоянная история результатов пока не ведётся.

Локальные файлы и маленькие JSON-указатели выбраны вместо дополнительной СУБД: для неизменяемых предметных пакетов не нужны транзакции между отдельными строками.

## Автоматический импорт

Workflow .github/workflows/content.yml выполняется при изменениях инструментов/банков, вручную и ежедневно в 01:17 UTC (06:17 по Ташкенту). Запуск по расписанию начнёт работать после попадания workflow в main.

При push сначала публикуются версии встроенного bootstrap-каталога. Уже существующий актуальный каталог при этом не заменяется начальным. Затем выполняется полный импорт НЦТ. При ошибке исходного сайта или разметки последняя опубликованная база продолжает работать.

Импортёр:

1. Разбирает первую таблицу компонента А на таджикской странице, связывает задание и ключ по одной ячейке таблицы. Не выводит адрес ключа из суффикса имени файла.
2. Проверяет наличие всех десяти поддерживаемых предметов и согласованность годов. Компонент Б и русскоязычные предметные банки не смешиваются с компонентом А.
3. Загружает оба PDF и сравнивает SHA-256, поэтому замечает замену файла по прежнему URL.
4. Импортирует изменённый предмет во временную папку. Сверяет весь поддерживаемый раздел с одним правильным ответом с ключами.
5. Публикует новый каталог только после успешной подготовки всех предметов. Несовпадение номеров, пропуски и нераспознанные ключи останавливают публикацию.

Состояние источников кэшируется Actions в .source. Исходные PDF не добавляются в main. Диагностика неудачного импорта сохраняется как workflow artifact.

Ограничения: импортёр адаптирован к текущим макетам НЦТ, использует текстовый слой PDF и сохраняет сложную типографику изображениями. Скан без читаемого текста потребует OCR/адаптации: такой материал автоматически не публикуется. Задания на соответствие, краткий ответ и общий текст английского раздела пока не включены.

## Команды разработчика

    python -m pip install -r tools/requirements.txt
    python -m unittest discover -s tools -p "test_*.py" -v
    python tools/content.py

Проверка настоящего импорта одного предмета без публикации:

    python tools/sync_ntc.py --subjects law --limit 25
    python tools/sync_ntc.py --subjects law

Полный импорт и подготовка публикации:

    python tools/sync_ntc.py

Обновление bootstrap после намеренного изменения начальных банков:

    python tools/content.py
    # Скопировать .content/catalog.json в app/src/main/bootstrap/catalog.json.

Публикация из checkout с правом push в репозиторий:

    python tools/publish_content.py

Для обычного использования достаточно workflow: он получает ограниченный токен GitHub Actions автоматически. Токен не передаётся приложению.

Проверки Android:

    .\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
    python tools/check_apk.py app/build/outputs/apk/debug/app-debug.apk

tools/smoke_content.py предназначен для эмулятора с установленным APK на главном экране. Он проходит 25 вопросов, завершает процесс приложения и восстанавливает ответ, скачивает кластер, отключает Wi-Fi/мобильные данные для проверки офлайн, затем включает их обратно. Сценарий удаляет скачанный тестовый пакет таджикского языка и сохраняет протокол в preview/v05-content-results.json.
